## Decisions

- **P1 Markers.** Every issue that import makes starts with `<!-- bosun:plan <id> -->` (`M2` for
  an epic, `M2/T1` for a task, `M2/P` for the plan task). Import finds existing issues by that
  marker among the issues labelled `bosun:source/plan` (any state), so a second import creates
  nothing (UC-M2-1). Tasks also carry the seed's `<!-- bosun:task {json} -->`; epics carry
  `<!-- bosun:epic {"item","area","plan","depends","ucs"} -->`.
- **P2 The plan task.** Each item gets one plan task `<item>/P` (title `<item>/P: pending UC
  tests`, `bosun:kind/plan`, state `ready`, `allow = ["skip"]`, touch = its UC test file). It is
  the PR that adds the item's pending UC tests. The item's tasks start `planned`; `plan import`
  moves them (and the epic) to `ready` only when `<item>/P` is closed as completed or labelled
  `merged` (UC-M2-2). This closes the PROGRESS follow-up: plan tasks allow `skip`.
- **P3 UC stubs.** For a `rust` stack, import writes the missing UCs of each item to
  `tests/uc_<item lowercase>.rs` in the working tree as `#[test] #[ignore = "UC-M2-1"] fn
  uc_m2_1() { todo!(..) }` with the UC text as a doc comment. A UC whose id already appears in
  any file under `tests/` is not written again (UC-M2-3). Other profiles: no stubs, a note in
  `data`.
- **P4 Amend.** `bosun plan amend <file>` = import, then reconcile: epics and tasks of the same
  plan file (`plan` in the metadata) whose id is gone from the plan close as `not_planned`
  (UC-M2-4); changed titles and metadata are updated in place. `Issue` gains `state_reason`;
  `wave plan` no longer counts a `not_planned` issue as merged.
- **P5 Intake.** `bosun intake "<text>" --source slack|lesson|flake|human [--item ID]` opens one
  `bosun:kind/plan` issue (state `ready`, `bosun:source/<source>`, touch `plans/**`, allow
  `skip`) whose body says: amend the plan file, open a kind/plan PR, run `bosun plan amend`
  after it merges.
- **L1 Lesson issues.** A lesson issue has label `bosun:lesson` and the marker
  `<!-- bosun:lesson {"signature","kind"} -->`. `core::signature` normalises a failure text
  (hex ids, numbers, timestamps, temp paths, whitespace) and hashes it (FNV-1a 64, hex).
- **L2 Capture.** `bosun lesson capture --kind <k> --issue N [--title T] --from -|FILE` (kinds:
  `stop-rule`, `blocked`, `flake`, `review-ask`, `budget`, `gate-budget`, `main-red`) and
  `app::capture_lesson` for other commands: an open lesson with the same signature gets a
  `lesson-seen` record comment (a hit), else a new lesson issue opens (UC-M5-1). A closed
  lesson that was mechanized reopens as blocking (UC-M5-5, task 8).
- **L3 Process-red.** Any open issue labelled `bosun:process-red` (a blocking lesson carries
  it). `claim` and `spawn` refuse non-`mainfix`/`process-fix` work with exit 4 and `wave plan`
  returns exit 4, as on main-red (UC-M5-2).
- **L4 Triage.** `bosun lesson triage <issue> --as blocking|mechanizable|advice`: blocking adds
  `bosun:process-red` and `bosun:lesson/blocking`; mechanizable opens a `bosun:kind/process-fix`
  task (`--touch`) linked to the lesson; advice adds an entry to `docs/lessons.toml` and closes
  the lesson. The curator Routine prompt in `doctor` calls it.
