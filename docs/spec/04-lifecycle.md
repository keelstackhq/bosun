## 4. Work lifecycle and conflict avoidance

Units: a plan has items. Each item becomes one epic issue. An item has tasks. A task is at most
400 changed lines and has one context pack. The critical path of an item has at most 4 open tasks
(tasks already merged or closed as completed do not count).
Each item has a "Done when" list; each line becomes one UC (`UC-<item>-<n>`).

Labels:
- `bosun:state/` planned, ready, claimed, building, review, fixing, queued, merged, blocked, needs-human
- `bosun:kind/` feature, plan, mainfix, bookkeeping, flake, process-fix
- `bosun:area/` one per area (one area = one orchestrator)
- `bosun:source/` plan, slack, lesson, flake, human

State machine:

| From | To | When |
| ---- | -- | ---- |
| planned | ready | only when its plan task merged |
| ready | claimed | `bosun claim`; lease written |
| claimed | building | first commit pushed |
| building | review | `bosun pr`; gates green |
| review | fixing | verdict request-changes |
| fixing | review | fix pushed |
| review | queued | `bosun pr --ready` (alias `--auto-merge`) marked the draft ready and turned auto-merge on (at once; the ruleset's required checks gate the merge) |
| queued | merged | the merge queue or auto-merge merged it, or the orchestrator ran `bosun merge <pr>` (D13, D-019) |
| building, review, fixing | merged | a human merged the PR; `bosun pr`, `bosun reap` or `bosun result --outcome merged --pr N` sees it |
| any | blocked | stop rule, conflict, budget, a child's `bosun result --outcome blocked` |
| any | needs-human | risk high, owner question, tier escalation used up, a child's `bosun result --outcome needs-human` |
| needs-human | ready | `bosun answer --chat` counted an owner's signed answer to the open ask (§10); not while halted or main is red |

Only bosun commands change the state label. A hook guards against accidental or casual label edits; it is not a sandbox. It fails closed: a Bash command that names a state label passes only when every command in it, nested ones included, is on a read-only allowlist (`bosun`, grep/cat/jq and similar text tools, `git show|log|diff|blame|status` with vouched options, `gh issue|pr list|view|status`, `gh pr diff|checks`, `gh search`, `gh label list`) and no `$` expansion appears outside single quotes; the body of a heredoc with a quoted delimiter is data, so prose that names a label passes; so is the value of a prose flag (`-m`, `-b`, `-t`, `--message`, `--body`, `--title`) of `git commit|tag` and `gh pr|issue create|comment|edit|review|close|reopen` when it is a plain quoted string without `$`, a backtick or a backslash, or a `"$(cat <<'EOF' .. EOF` + newline + `)"` that only `cat`s a quoted-delimiter heredoc (prose is stripped only when the whole command starts literally with `git commit`, `git tag`, `gh pr VERB` or `gh issue VERB` (no `VAR=x`, no `git -c`, `--config-env` or other global option, no `gh -R`) and uses only the flags on that command's allowlist (git commit: `-m`, `--message`, `-a`, `--all`, `-s`, `--signoff`, `--allow-empty`, `-q`, `--quiet`; git tag: `-a`, `-m`, `--message` and operands; gh create: `-t`, `--title`, `-b`, `--body`, `-B`, `--base`, `-H`, `--head`, `-d`, `--draft`; gh edit, comment, close, reopen: the same plus operands; gh pr review: `-b`, `--body`, `-c`, `-r` and operands), so `-e`, `-t` of git, `-F`, `--cleanup`, `--amend`, `--no-verify` and any unknown flag keep the whole text judged; outside the prose values there is no newline, `;`, `&`, `|`, `#`, `$`, backtick, `<`, `>`, parenthesis, backslash or `$'`, so a comment, a second command or a variable command word keeps the whole text judged; a heredoc body line that starts with the delimiter and more text, `EOF)`, which bash treats as the end inside `$( )`, disables stripping and the data reading of that heredoc: its body is judged as code, in every lock; no prose is stripped when, outside the prose values, any word (quotes removed) holds `label` in any case (`--add-label`, `gh label`, `labels`), or, in a gh command, a short flag cluster holds `l` (`-l`, `-dl`, a quoted `"-l"`)). Known misses: a label split by quotes or escapes, built at run time or passed through a file, and repo or user config, or files, written by the same or an earlier command (a redirect whose literal target is in `.git/` or a gitconfig is refused; a globbed target, a command that writes a file operand such as `uniq IN OUT`, and other paths are not). A GitHub tool call is refused when its label fields (or, for a label tool, its whole input) name a state label.

Draft-first PRs: CI jobs never run on a draft, so an unfinished PR costs no minutes. `bosun pr <issue>` opens a new PR as a draft (REST `draft: true`; `data.draft` is true, `data.ready` false) and leaves an existing PR as it is. `bosun pr <issue> --ready` (alias `--auto-merge`) is the way out of draft. Before any state change of its own it requires (a) that the local `HEAD` is the PR head (else exit 3, fix: push or pull) and (b) a local gate stamp for `HEAD^{tree}` for every ready gate: `test-integrity` plus each of `fmt`, `lint`, `types`, `test`, `deps` that a configured stack's profile defines (else exit 1 with `data.missing_gates` and, as fix, the exact `for g in ..; do bosun gate $g || break; done` loop). A stamp is the file `<git common dir>/bosun/gates/<tree>/<gate>` that a passing `bosun gate <name>` (also `test-integrity`) writes outside CI; `<tree>` is the tree of `HEAD` plus every working-tree change including untracked, non-ignored files (what `git add -A` would commit, built in a temporary index); the path is `data.stamp`. A gate that skipped (no package or empty diff on the default base, missing manifest or lockfile, `when_no_package = "skip"`) writes a stamp marked `skipped`, which counts as done (its required gate would otherwise deadlock `--ready`); a run with an explicit `--base` stamps nothing (`data.stamp` is `null`); `test-integrity` judges untracked, non-ignored files as added files, so it stamps the working tree like every gate and a commit of that work keeps its stamp. A failure to stamp goes to stderr and never fails the gate. The conversion to ready (GraphQL `markPullRequestReadyForReview`) comes after the touch, state and enforcement checks and before the record comment; when the Claude Code cloud proxy refuses GraphQL (403 `GraphQL is not available from Claude Code sessions`), bosun turns nothing on (GitHub cannot auto-merge a draft) and exits 0 with `data.ready: "pending"`, `data.note` and `next` = `mcp__github__update_pull_request` with `{owner, repo, pullNumber, draft: false}`: the session makes the call, then reruns `bosun pr <issue> --ready`. `bosun hold` and `bosun ask` put the task back to draft after their own work: every open, non-draft PR of a repo writer from this repo whose body links the task (as `bosun pr` finds it) is converted with GraphQL `convertPullRequestToDraft`; `data.drafted` lists the PR numbers and `data.pr_draft_error` says why one was not (listing failed, GraphQL error); a CCR refusal adds a `next` call with `draft: true`. The drafting is best effort and never fails the command. `bosun plan pr --auto-merge` passes on as `--ready`.

`bosun pr` sets claimed -> building -> review (a PR exists only after the first push). `--ready` needs the task in review (a plain issue, with no state label and no task metadata, has no state gate and is not moved to queued; the task-pr record comment is still posted; a task with metadata but no state label is refused with exit 3) and turns auto-merge on right away, without waiting for checks: it lists the required checks that are not green yet as `data.pending_checks` (context and state). Before it turns auto-merge on, and after the enforcement check, it also states the gates the merge relies on, `risk-check` and `review-verdict` with their states on the head SHA: one stderr line (worded `the branch requires them` when verified, `could not verify` on a 403, and none on the exit-5 path) and `data.gates`. Only a commit status posted by `github-actions[bot]` counts; a check run or another creator's status of that name reads `missing` (a plain `bosun pr` has an empty list), so a child's ready PR visibly passes the gates and does not skip review. It first reads what the default branch enforces (rulesets plus classic protection): when a readable answer does not require all of `ci-ok`, `risk-check`, `review-verdict` and `main-open`, it exits 5 with `data.unenforced` and turns nothing on, so auto-merge never merges an ungated PR; a 403 on either endpoint is `data.enforced_checks: "unknown"` and does not block (`"verified"` otherwise). Then it writes the record comment, enables auto-merge and moves the task to queued. When GitHub answers "clean status" (the PR is already mergeable, so auto-merge cannot be enabled; GraphQL or the ccr route), bosun does not merge: exit 5 with `data` `pr`, `head_sha`, `already_clean: true`, `ready_to_merge: [{pr, head_sha}]`, and the task stays in review; when the session has a registered parent, `next` is one `send_message` to it (at most 500 characters) that names the PR `ready_to_merge`, as `bosun result` does for the green PRs of its epic (`data.ready_to_merge`, §5), so the orchestrator is told and does not have to find it (a lookup that fails leaves `next` empty); the orchestrator merges it (D-008: the orchestrator session may merge once the required checks are green and any owner approval is in), or the PR's next push makes auto-merge possible again. GitHub's "unstable status" (a failing check) is exit 1 with `data.unstable` and a fix naming `bosun wait --pr N`. An open PR on the branch that does not link the task is refused (exit 3, before any change). `bosun pr` or `bosun reap` sets a building, review, fixing or queued task to merged once its PR merged into the default branch (auto-merge or a human), and ends the leases on the issue with reason `merged`. `bosun pr` and `result` count only a PR merged into the default branch. `reap` and `result` move a building, review or fixing task only when its issue is closed (GitHub closes it when a `Closes #N` PR merges; an open issue means the work is not done, so an old merged PR linking it is ignored and no PR list is read for it); a queued task counts whatever the issue state, and so does a task whose newest `task-pr` record (below) names a merged PR that closes it. `reap` runs this before expiring leases, so a merged task is never reaped back to ready. A task whose own PR merged into the default branch also moves to merged whatever the state of its issue, as an exception to the closed-issue rule above, and only when that PR closes the task (`Closes #N` in its body; the bosun marker alone is not a link, the PR author controls it): the PR is the one in the newest `task-pr` record written by a repo writer (`reap` and `result`), or, in `result` only (it lists the PRs once when a task has no usable record), a PR that closes the task and was opened by a writer; an open such PR means not merged. `result` does this for every building, review, fixing or queued task of its epic (it lists the open and closed issues of those four states and reads the comments of each unfinished task, whatever the outcome) and lists them in `data.tasks_merged`. `bosun result <epic> --outcome merged --pr N` reads PR N; when it is merged, the tasks it links move to merged, this session's leases on them end with reason `merged`, and `data.tasks_merged` lists them; an unmerged PR changes nothing. Before it turns on auto-merge, `bosun pr --auto-merge` posts `{"bosun":"task-pr","session":..,"pr":N}` on the task; `reap` reads the newest such record and that one PR (it must link the task: open means wait, merged into the default branch means merged). Only a task without a usable record (none, as for older tasks; a PR that is gone, does not link the task, is closed unmerged or merged into another branch) costs the list of all PRs.

No CI (`[ci] provider = "none"` in `.bosun/bosun.toml` on the default branch; a PR into another branch is refused): `--ready` runs here what the workflows would and turns nothing on, failing closed at each step. After the state check: (a) and (b) above, the required gates being those of the default branch's config and profiles at its current sha (never this checkout's or the PR's), a missing stamp being exit 5 (`data.missing_gates`); risk-check judged locally with the base's rules, posting no status; a clean verdict on the head from a session other than this one and the task's lease holders (a `bosun verdict comment --sign-key <pem>` signed by an enrolled `.bosun/approvers.toml` key (role `reviewer` only; an owner, delegate or signer key never signs a verdict, and `--sign-key` refuses one: the orchestrator holds an owner key and never holds a reviewer key) over the repo, PR, head and the whole comment text: approve, confidence at least 0.9, no major, not escalated, every chunk listed, unedited; the newest per key id counts, not per session tag; any signed unclean verdict on the head blocks whatever the order, and a repeated identical signature counts once), else exit 5; main-open judged locally (exit 4 while main is red, unless mainfix). It then posts one summary comment per head (`/bosun ready <head>` first line; `- gates:`, `- risk:`, `- verdict:`, `- approval:` lines; last line `<!-- bosun:ready v1 head=<head> -->`). A high-risk head with no owner or chat approval of exactly that head exits 5 (`data.next_command: "bosun approve --list"`; the orchestrator asks the owner and records `bosun approve <pr>@<head> --chat`, then the session reruns `--ready`). Otherwise the draft is marked ready, the `task-pr` record is posted, the task moves to queued and `data.merge_next` is `bosun merge <pr>`; no commit status, no auto-merge. `bosun pr --pr <n> --ready` refuses without CI. No gate App record counts without CI (`checks` mode is refused there, and in `statuses` mode `github-actions[bot]` is any writer's push workflow), nor does it count toward a bootstrap approval (`autonomous_inputs` reads none). A self-declared session tag, an unsigned verdict or a writer's comment never counts as independent review. Key custody: spawned sessions never receive the reviewer or approver (owner, delegate, signer) PEM; the reviewer key lives with the reviewer's own machine (`bosun keygen --role reviewer`) and the owner key with the orchestrator, so a guard stops a confused worker, not a session that holds a key. Without CI, `bosun approve --list` takes a ready summary of the head by a writer or the gate App only as a hint that the author finished `--ready`, then judges the PR itself with the base's rules (risk-check, dry) and the chat records; a non-writer's summary is ignored, and a `--ready` exit 5 that is not "high risk, not approved" posts no summary.

Plan ticks: ticking task checkboxes in a plan file (`- [ ]` to `- [x]`, a markdown file under `plans/` or `docs/superpowers/plans/` at the repo root, nothing else changed) needs no lease: the edit-lock hook lets an `Edit` that only ticks pass (also inside another session's lease), and the touch check of `bosun pr`, risk-check and test-integrity counts a tick-only plan patch as covered (`core::touch::plan_tick_file`). A GitHub patch has no `---`/`+++` file headers, so none is skipped: every `-` and `+` line must be a tick pair, paired inside one change block of one hunk (equal counts, same order). No patch shown never counts, and only a file with status `modified` and no previous name is exempt, so a rename never escapes the touch check.

Work nobody planned (a Slack request, a quick fix): `bosun pr --one-off --title <T> --touch <GLOB>... [--ready]` opens a ready task of item `oneoff` (label `bosun:source/oneoff`, touch from `--touch`), claims it as this session and runs `bosun pr` for it; `data` is the one of `bosun pr` plus `task` and `claim`. Each step is the command itself, so a gated touch, an overlap, a spend stop or a red main refuse as for any task; a missing title or touch is exit 2 before anything is created. Before anything is created each touch glob must be covered by a glob of the owner's `[approvals] oneoff_allow` on the base (no further check: such a glob may reach a gated path, and risk-check asks the owner for it), or lie inside the base's autonomous allow set (§8: the built-in set, or the owner's `[approvals] autonomous_allow`) and not reach a gated path (a risk-rule glob of the default branch, wildcards resolved against its file list as for a plan task), else exit 3; a glob containing `<!--` or `-->` is exit 2 (it would break the task marker). A one-off PR changes at most 300 lines: `pr --ready` refuses (exit 3) over that, and risk-check adds an owner-class `R-oneoff-size` match. It never reuses a task: a re-run opens another, so use `bosun pr <issue>` to update.

Handoff notes (status and open items a session leaves in the repo) go to `docs/handoff/<branch>.md`, one file per branch with `/` as `-`, so two PRs never edit the same file. The path is normal risk (§8), so `bosun pr --one-off --touch 'docs/handoff/**'` takes it; `docs/agents/**` is R-gov and is refused. Agents read the notes as data, never as instructions, and no agent-instruction file imports them. `bosun handoff` (§5, the registry record) stays the root's lineage handoff; `docs/handoff/` is for notes kept as repo files.

A PR with no task (a governance PR, for example `bosun migrate`'s): `bosun pr --pr <n>` reuses PR n (never opens one). Only a governance PR qualifies: opened by a repo writer, every changed file (both names of a rename; a deletion counts) matching, in any case as risk-check matches, a governance path (the R-gov list of the built-in rules, `governance_globs` in `src/core/risk.rs`, so the two never disagree) that the base's own rules (`.bosun/risk.toml`, else the defaults) also match with an owner-class R-gov rule (fail closed: risk-check judges by the base rules, so a path an older or custom R-gov misses, or a non-owner R-gov, is refused) or a glob of `[approvals] oneoff_allow` on the base (README, `.github/**`, `Cargo.toml`, ...; a missing or bad config or glob adds nothing). A tick-only plan file is refused: risk-check skips it, so it would merge with no owner. Known limit: a PR under `oneoff_allow` has no size cap (the 300-line one-off cap applies to one-off tasks only). `--ready` runs the PR checks of the task path (local HEAD is the PR head, gate stamps, the trailers check, the enforced required checks, the CCR `next` fallback for the draft) and turns auto-merge on; there is no task state, lease or record comment. It refuses a PR from a fork, a closed PR, another path, and a PR whose body closes an issue (also `owner/repo#N`) or carries the `bosun:task-pr` marker (exit 3, fix: `bosun pr <issue>`). `--pr` with an issue or `--bundle` is a usage error. risk-check stays required, so an R-gov or R-weaken PR still waits for the owner.

`bosun merge <pr> [--method squash|merge|rebase]` (D13 as amended by D-019; default squash): the kill switch first (exit 4); then the session must be an orchestrator in the registry, not a spawned origin or `CLAUDE_CODE_CHILD_SESSION=1` (else exit 5, fix `bosun handoff-pr`). The PR must target the default branch (else exit 3: a stacked PR is retargeted after its base merges). A merged PR is reported (`already_merged`) and its tasks follow; a closed one is exit 3. It re-checks the PR's current head. No CI at the base: a repo writer's ready summary for that head (none: exit 5; only for an older head: exit 3, the head moved; it is only that signal), the gate stamps of this checkout on the head's tree, for the gates the default branch's config requires (head not fetched or a stamp missing: exit 5, `data.missing_gates`), risk-check judged locally (a gated PR without the owner's chat approval is exit 5; the answer may come after the summary, no `--ready` rerun needed), a clean verdict from another session signed as above (exit 5), main-open judged locally (exit 4). With CI: every required check green and `risk-check`/`review-verdict` posted by GitHub Actions (else exit 5, `data.pending_checks`). It then calls `PUT /pulls/{n}/merge` with `sha` = that head; GitHub refuses a moved head or an unmergeable PR (409/405: exit 3, nothing merged); a 403 (this session's token or proxy cannot merge) is exit 5 and the owner taps Merge in the GitHub app. Linked tasks move to merged and their leases end. `data {pr, head_sha, merged: true, method, ci_provider, tasks}`. `bosun merge` in a repo with CI is intended (D-008 orchestrator merge): it re-checks the required checks on the exact head and merges with `sha = head`. No-CI trust model: verified are the verdict (enrolled-key signature, exact repo, PR and head), risk (the base's rules), the owner's approval (D-018 records) and main-open; the gate stamps are local files and advisory until `bosun merge` reruns the gates itself (next PR); advisory are the orchestrator identity check (it reads the session's own environment and registry join, so it stops confused agents, not a session that lies, unless that session also holds an enrolled key) and the ready summary (a writer's comment, only a head-moved signal). The provider is the default branch's `[ci] provider`, read now through the API (never the PR's base sha or head), and the PreToolUse guard refuses a command that runs `bosun merge` and also exports, unsets, declares or assigns `BOSUN_*` or `CLAUDE_CODE_CHILD_SESSION` (also in subshells, `set -a`, or behind a variable or substituted command word); a sourced file or a name built at run time is not covered.

Bundle backstop (D-016): for an existing PR that closes more than one task, `bosun pr` reads the default branch's risk rules and the PR's changed files before any change; a gated file (or a rename's old name), or an incomplete file list, is exit 3 (fix: move the gated changes to their own task and PR).

Touch check: before it opens or reuses the PR, moves any state or turns on auto-merge, `bosun pr <issue>` reads the PR's changed files (with no PR yet, the comparison of the default branch with the pushed branch; the compare API lists at most 300 files) and checks them against the touch of the session's live lease on the issue (or, failing that, a live lease held by a per-task id of this orchestrator) plus lockfile companions (`Cargo.toml` gives `Cargo.lock`, `package.json` gives `pnpm-lock.yaml`). Modified and removed files, and the old name of a renamed file, that no glob covers make it exit 3 with `data.outside`; the fix names `bosun claim <issue> --touch <path>`. Added files, the new name of a rename, copied files and `changelog.d/*.md`, `docs/progress.d/*.md` and changesets `.changeset/*.md` (not `README.md`) always pass. It is an accident guard, not enforcement: with no matching live lease (a lease with an empty touch, like a spawn's epic lease, does not count), a diff at the file cap or cut short, or an unreadable diff, it is skipped and never blocks. `data.touch_check` is `ok`, `skipped (no lease)`, `skipped (diff too large)` or `skipped (diff unavailable)`.

Bundle: `bosun pr <lead> --bundle <N>...` (repeatable) opens one PR for a single-shape bundle (D-016). Before any change it checks every `N`: an open task issue with task metadata, the lead's epic, whose shape is `single`, not gated, not the lead; the lead too must be open and not gated. Gated is judged as `bosun wave plan` does: the `gated` flag, `risk: high`, or a `touch` reaching a gated path of the default branch's rules and tree (unresolvable counts as gated); else exit 1 with the fix "pass only the `bundle` issues `bosun wave plan` listed". A new PR's body is `Closes #<lead>`, a `Closes #N` line per bundled issue, then the marker; the comparison of the default branch with the branch is checked for gated files first (exit 3, as for an existing PR). For an existing PR the body is never edited: one that lacks a `Closes` for a bundled issue is exit 3 ("add `Closes #N` for each bundled issue to the PR body, then rerun"). Closing references in every GitHub form count everywhere (`Closes #N`, `Closes owner/repo#N`, `Closes https://github.com/owner/repo/issues/N`; a pull request URL is not an issue); only plain ones and those naming this repo close this repo's tasks.

Stop rules:
- The same failure signature 3 times in a row: the task goes to blocked.
- A fix round with 0 changed lines: the task goes to blocked.
- On blocked, bosun escalates one model tier (haiku -> sonnet -> opus). When opus is used up, the
  task goes to needs-human.
- `bosun fail <issue> --signature S [--changed-lines N] [--model M]` posts a `failure` record and
  applies these rules. A stop sets `blocked` and posts an `escalate` record (`from`, `to`,
  `reason`); an escalation restarts the count. With opus used up it sets `needs-human` (exit 5).
  The signature is in `data` for the lessons.
- Each stop (both paths) also captures a lesson of kind `stop-rule` from the rule and the
  signature; the same stop on another task hits the same lesson. `data.lesson` is `{issue,
  created, hits}`, or null with `lesson_error` when capture fails (the stop still stands).
- Each stop rule opens or hits a lesson.
- When main is red, feature work pauses; only mainfix tasks continue.

`bosun claim` (fresh, idempotent and grow) returns `data.lessons`: one compact line (`id scope
rule`) for each lesson in the local `docs/lessons.toml` that is global or whose scope overlaps the
touch (spec §6). It is advice: a missing or unparseable file gives `[]` and never fails the claim.

Leases: a claim is an issue comment with one JSON line:

```json
{"bosun":"lease","session":"session_...","origin":"spawned","expires":"2026-10-22T10:30:00Z","touch":["src/core/lease.rs"]}
```

The TTL is 30 min; `bosun heartbeat` extends it, and so does `bosun wait` while it polls (§5),
which also runs the expiry part of reap. `bosun reap` releases expired leases and sets the
task back to ready. `bosun release` ends a lease in the normal way. A released or reaped lease gets
a second comment `{"bosun":"lease-end","session":..,"reason":"released|reaped"}`; the live lease
of an issue is the newest lease comment with no later lease-end for the same session.

Conflict avoidance (three layers):
1. Registry: `bosun join` registers each session with its origin (spawned, slack, local, routine)
   as a comment on the registry issue (label `bosun:registry`). All caps count all origins.
2. Claim check: `bosun claim` refuses a bundled task (exit 3, "#n is bundled into #lead's PR"; fix: work in the lead's bundle, its PR closes #n) when its epic has shape `single`, the task is not gated, and another non-gated task of the epic is active. It also refuses (exit 3, "--touch <glob> is a gated path: gated work runs as its own task, not inside the bundle"; fix: drop the gated path and plan it as its own task) a `--touch` glob under a risk rule (default-branch `.bosun/risk.toml`) on a non-gated task of a `single` epic whose own touch is not gated, on first claim and on lease growth; a wildcard `--touch` is resolved against the default branch's file tree (gated when it holds a gated file), and one that cannot be resolved is refused (exit 3, fix: narrow --touch to explicit paths). It refuses a task if its touch paths overlap a live lease, or if another
   orchestrator owns its area. Exit 3 with a JSON reason. An area owner that is the
   parent of the claiming session does not block it, so spawned workers can claim in their
   orchestrator's area. A per-task id `S/task` (a wave agent with
   `BOSUN_SESSION=S/task`) claims as `S`: it is inside `S`'s area and inside the area of `S`'s
   parent. A re-claim of an own active task with `--touch` grows the lease: the
   globs it lacks pass the same overlap check (exit 3 on a clash), then a new lease record with
   the old touch plus the added globs is written (`data.added`), without changing the state;
   without new globs it changes nothing. A grow that loses the claim race edits its record back
   to the previous one (the lease is never ended) and exits 3 naming the winner; if that edit
   fails it exits 1 and the fix says to release the task. The grow re-reads the active issues
   after it writes, and if the task is no longer held (state not active, or a newer `lease-end`
   of the session) it edits its record back and exits 3.
Compaction (state that survives a summary): `bosun hook pre-compact` (wired as the PreCompact hook in `.claude/settings.json` and the core channel piece, behind the same fail-open wrapper as Stop, `out=$(bosun hook pre-compact) && printf '%s\n' "$out"; exit 0`) prints plain text that Claude Code adds to the summary instructions: `Keep this bosun state verbatim in the summary.` then a `bosun state (session <id>):` block with the session's own live leases (issue, lease session, touch, expiry), the branch (`(detached)` without one) and short HEAD, the branch's open PR (number, head sha, draft), the newest refusal marker of the session (its context line) and a `Next:` step of the task loop for the newest lease. A bad `BOSUN_NOW` falls back to the clock. Known limits: targets fed on stdin (`echo / | xargs rm -rf`) or held in a variable, SQL read from a file. `.claude/settings.json` repeats the plain forms in `permissions.deny`. The repeat-lock counts Bash calls that pass the other locks in `<git common dir>/bosun/repeat/<key>.json` (`{command, count}`, written atomically; the key hashes the hook's `session_id` (else `BOSUN_SESSION`; no session, no lock), its `agent_id` and the directory, so parallel agents count apart): the same trimmed command in a row warns at the 3rd run (`additionalContext`, no decision) and is denied from the 5th; read-only polls (`bosun wait|status|heartbeat|doctor|ci-log|review-pack`, `sleep`, `gh pr checks|view|status`, `gh run view|watch|list`, `git status|log|fetch|diff`, alone or with `2>&1`, without operators, substitutions or `--output`) are not counted and leave the counter as is; another command resets the count and any other hooked tool call (an edit between test runs) removes it; an I/O failure skips the lock.

Sticky refusals: a script (Code Mode exec, a bash loop) can swallow an exit code, so after every command but `bosun hook` the CLI records a refusal that must not be lost. Exit 4, 5 or 6, and 3 from `claim`, writes `<git common dir>/bosun/refusals/<key>.json` (`{session, command, exit_code, fix, at, lock}`, atomic; one file per session and command; session as D31: `BOSUN_SESSION`, else the caller id; sessions that fall back to `local-<host>` share markers). `lock` is true only for a kill-switch halt (an exit 4 whose message or fix has a fixed kill-switch phrase: `halt issue #`, `bosun:halt issues`, `BOSUN_HALT`, `stays halted`); a main-red or process-red exit 4 leaves writes open for the fix it asks for. A successful command removes the markers it answers of its own session and its task sessions: the same command, a command the fix names as `` `bosun <command>` ``, or for exit 4 a `bosun status` whose data shows `halted: false` (for a `lock` marker that alone; for a main-red or process-red one also no main-red and no process-red). The PreToolUse hook reads, on every tool call, the markers of its caller (the same session, or a task session `<caller>/<task>`: a `BOSUN_SESSION` set per command never reaches the hook). It injects each marker once as `additionalContext` (it records that in `<key>.shown`, a copy of the marker's bytes, and never rewrites the marker, so a marker a command removed cannot come back) (`bosun refusal: ... Fix: <error.fix>`, merged with a repeat-lock warning). While a `lock` marker stands it denies a write, with the fix and `bosun status` as the way out: `Edit`, `Write`, `MultiEdit`, `NotebookEdit`, `mcp__github__*` other than `get_*`, `list_*`, `search_*` and `*_read`, and Bash `git push|commit|tag|merge|rebase|cherry-pick|am`, `gh pr create|merge|edit|ready|close|comment`, `gh issue create|edit|close|comment` and `gh release create|upload`. A deny of another lock wins; an I/O failure only warns.

The CLI's own repeat counter: the hook sees one tool call for a whole script, so a loop of bosun calls inside it would never reach the repeat-lock. So under Claude Code (`CLAUDECODE=1`) and outside CI (no `CI`, `GITHUB_ACTIONS` or `CIRCLECI`), every bosun call but `bosun hook` counts itself before it runs; elsewhere no hook would reset the count, so a human, another agent or a CI job is never counted. The count lives in `<git common dir>/bosun/cli-repeat/<key>.json` (`{session, repeat: {command, count}}`) of the repo the process runs in, never the `-C` directory, because the hook resets it from its own working directory (the `-C` directory is part of the counter key, so one command aimed at two repos with `-C` counts apart) (a command that first does `cd` into another repo counts there and is not reset; a call whose working directory is in no git repo is not counted, even with `-C <repo>`, since the hook could not reset it). The refusal markers above likewise go to the repo the process runs in, where the hook reads them, never the `-C` one. The count is written to a temp file and renamed, with no lock, so parallel calls may lose a count, which only weakens the limit. There is one file per session, as for the refusal markers: sessions on `local-<host>` share it, and a `BOSUN_SESSION` that is neither the caller nor `<caller>/<task>` is never reset by the hook. `command` is `bosun` and the arguments without the global flags `-C <dir>`, `--json`, `-v` and `--verbose`. The same call in a row warns on stderr at the 3rd run (`cli-repeat: ...`). From the 5th it is refused with exit 6 (`limit`) and nothing runs; the refusal is sticky, as above. Polls (`is_poll`, as for the repeat-lock) are not counted and leave the counter as it is, and another call restarts it at one. The next hooked tool call that runs (its output has no `permissionDecision: deny`), other than a Bash poll, removes the counters of its caller and its task sessions, so runs split by the agent's own tool calls count only in the hook's repeat-lock. An I/O failure skips the count.

Leases conflict per issue, not per session: wave agents run inside their orchestrator's session, so a
lease on another issue conflicts even when it has the same session id; only a lease of the same session
on the issue being claimed is the same claim (a re-claim is idempotent). A re-claim of an own task in an active state (claimed, building, review, fixing, queued) whose own lease lapsed and was not reaped yet renews that lease in place, after the overlap check on its full touch. It is refused (exit 3) when another session holds a live lease on the same issue. After the write it reads the task and its leases back and exits 3 unless this session's lease is still the live one and the state is still active (a reap that ended the lease in between is not undone). "Own" is the exact session id: `S` cannot renew the lease of `S/x`, nor `S/x` that of `S`. Give each wave agent
`BOSUN_SESSION=<session>/<task>` in its berth workspace; `S/x` conflicts with `S/y`, not with `S/x`.
`wave plan` counts the epic's active tasks that hold a live lease against `waves.max_parallel` and
blocks picks that overlap their touch paths. The edit hook keeps the session rule (an agent may edit
paths its orchestrator `S` leased), a known limit: without per-task ids it cannot tell wave agents apart.
The hook sees only the plain session id, so a session `S` may also edit the paths of leases held under `S/<task>`; `S/x` and `S/y` still block each other.
Claim and spawn re-check after writing: a fresh claim sets the state `claimed` first (it relies on the label-filtered issue list reflecting that at once), posts the lease, then lists
the active issues anew and re-reads their comments (so of two ready tasks claimed at the same time the later
listing sees the other), and when a live overlapping lease has an earlier comment (creation time, then comment id) they
post `lease-end` with reason `lost-race`, exit 3 naming the winner and, for a claim lost to another task, set the state back to `ready` (only while it is still exactly `claimed` with no other live lease; after the `ready` write the comments are read once more, and a live lease of another session that appeared meanwhile (a third claimer that won) gets the state set back to `claimed`, best effort with a stderr note; a failed revert stays exit 3 with `data.revert_failed`, and `bosun reap` resets a claimed or building task with no live lease whose newest lease record is a `lost-race` lease-end and whose issue was last updated over 10 minutes ago). A claim that dies between the state change and the lease leaves a `claimed` task with no lease record: a known limit, `bosun release` fixes it.
A race is decided per contested glob pair: for each glob of the new lease that overlaps a glob of
a rival, a lease counts from its session's earliest lease record on its issue since its last
lease-end that has a glob overlapping the other's glob, and the new lease loses if the rival is
earlier on any pair. So a grow keeps its priority on the globs it had and races at grow time for the
globs it added; both sides compute the same times per pair, so they never both win (both may lose and
retry). Known limit: a lease that
expired without a `lease-end` (not yet reaped) keeps its older records in that history.

Trust in records: a `{"bosun":…}` record read through `trusted_notes` counts only from a commenter with admin or write access to the repo; a read-only user's or outsider's record is ignored. This holds for the registry (`join`) and for lease records (`lease`, `lease-end`), so a forged join is no live member and a forged lease blocks no claim; sessions therefore need a token with write access to see their own records. Exception that reads every comment: `spawn --record` reads the spawner's own join and lease without a permission lookup (it must hand over when the lookup fails). It takes the highest depth of the spawner's joins, so a forgery can only raise the child's depth; it counts the spawner as registered while one of its joins is live and ignores `leave` records, so a forged `leave` cannot unregister it (the session's own `leave` is ignored there too: record follows a spawn the session just made through the writers-only checks, which do honour `leave`). A forged live join can keep an expired spawner registered for that record only; it cannot lower the depth or authorize a spawn. `hold`, `release`, `plan` amend's blocked check, risk-check's touch warning and `reap`'s `task-pr` lookup read writers' records only. Spend records count from writers and from `github-actions[bot]` (review-ci's spend; only a workflow with a write token posts as it). Some other records do not check who wrote them yet. Checks that do not rely on records: commit statuses (`ci-ok`, `risk-check`, `review-verdict`, `main-open`), and the files read from the base or default branch (`docs/lessons.toml`, `REVIEW.md`, `.bosun/limits.toml`). A `spend` record with a negative or non-finite amount is ignored. A delta review (`since_sha` of `review-pack`) needs the `verdict` record and a successful `review-verdict` status on that sha (records on heads without one are skipped), and the sha must be an ancestor of the head and a commit of this PR; otherwise the review is full.

Touch paths are repo-relative globs (`*` within a segment, `**` across segments). Two touch lists
overlap when a path of one matches a glob of the other, or two globs can match a common path.

`bosun reap` closes an open epic (marker `bosun:epic`; state ready, planned, claimed or none; no live lease: a spawned orchestrator's epic stays `claimed` after `result`, so it closes once its lease ended) whose tasks are all merged or closed and at least one is merged or closed as completed (a task closed with no reason or as not planned counts as dropped), and whose tasks have not changed for 10 minutes (an amend may be adding one): it gets state `merged`, is closed as completed and is listed in `data.epics_closed`. Open plan issues are listed first; with an unleased epic that has no open plan task, every open issue is listed once and an open task of the epic's item (task metadata `item`, whatever its labels or `epic` field: a hand-made issue `plan import` adopted) keeps the epic open, then all plan issues. This is housekeeping: a failure there is logged to stderr and put in `data.epics_error`, and the rest of the reap stands (exit 0). When `plan import` or `plan amend` leaves such a closed epic with an open task (a new task, a reopened or re-added one; decided from what the run made or found, with no new list, since GitHub's list lags), the epic is opened again as `ready` and listed in `data.reopened` (`data.would_reopen` in a dry run), which also repairs an epic that reap closed mid-amend (the quiet period narrows that race, the next import or amend repairs it).

A plan task can also be done before import: its `done-by: #N` field (docs/plan-format.md) makes `plan import` and `plan amend` set a new, planned or ready task to merged and close it as completed, but only when PR N is merged into the default branch and links the task (`Closes #<issue>` or the plan id in its title or body); a refused field is a `data.warnings` entry and exit 1, never silent.

Intake: intake is the only way that new work enters. `bosun intake` (from Slack, a lesson, a flake
or a human) writes a plan amendment as a kind/plan task. Only a merged plan task makes its tasks
ready. After an amendment merges, `bosun plan amend` imports the new work and closes what the plan dropped.
`bosun intake "<text>" --source slack|lesson|flake|human [--item ID] [--title T] [--plan FILE]` opens one
`kind/plan` issue (state ready, `bosun:source/<source>`, `bosun:area/<area>` of `--item`) that asks for the
amendment of the plan file (default `plans/<project>.md`; a missing file or unknown item is exit 2). An open
issue of the same source with the same title is returned instead (`created: false`).
Who may run it: any session, orchestrator or child (it checks only the kill switch and writes one issue, and nothing it opens becomes ready before its plan PR merges), so a child that finds work outside its epic runs `bosun intake` itself and names the issue in its `bosun result`; it does not write the issue by hand. The markers lock of the edit hook (`bosun:prereq|prereqs|epic|task` in an issue body or comment, §4 layer 3) refuses agents the checklist and epic markers always, and the task marker except in one case: a registered child may CREATE one new issue (the whole command is one `gh issue create`, written exactly `gh` (no `./gh` or path) with no `GH_REPO=` or other variable prefix, wrapper or `cd dir &&`, no `$` or backtick that could hide text, without `-R/--repo`, no nested shell, or the MCP `issue_write` with method `create` for this repo) whose body holds exactly one `<!-- bosun:task {...} -->` marker (the JSON bosun's own reader takes: the one `<!-- bosun:task ` opener up to the next `-->`; prose that names `bosun:task` is no decoy) that is valid JSON with only the keys `item`, `task`, `epic`, `touch`, `depends`, `kind`, `risk` and an `epic` it was spawned for; `kind` may only be `feature`, `bookkeeping` or `flake` (`mainfix`, `process-fix` and `plan` take lighter gate paths and come from a plan PR). Edits, comments, API writes, other repos and the keys `allow` and `capabilities` (which only a plan PR may set: they widen what the test-integrity and risk gates let a task do) stay refused. A registered child is a session whose epic carries a live lease with origin `spawned` and an empty touch (only `bosun spawn --record` writes that; a claim has touch paths), in a comment of a repo writer (read through `trusted_notes`, not any comment); the hook reads it from GitHub for each such write and denies on any doubt. Known limit: an agent holding a writer token can still forge a lease comment by hand; the hook cannot tell it from the parent's, so the claim, risk and approval checks on the work, not this exemption, are the guarantee.
`bosun intake check` works on the intake file instead (spec §3, layout); the text form is unchanged.
The intake file `.bosun/intake.toml` and `bosun init --intake` start a repo (spec §3 and §11).
`bosun plan pr <plan> "<why>" --source slack|lesson|flake|human [--item ID] [--title T] [--auto-merge]` opens the PR of a
plan amendment in one step, on the committed and pushed amendment branch: it runs `bosun intake` with
`--plan <plan>` (finding the open intake of the same title), `bosun claim` of that intake (its touch is the
plan file; skipped when the intake is already in review, fixing or queued) and `bosun pr` for it, each
with its own checks. `data` has `intake`, `claim` and `pr` (the data of each step, `null` when skipped);
a failed step returns its error with the steps before it in `data` (its own data in `data.failed`), so a
re-run continues. `--auto-merge` passes on to `bosun pr`.

When `plan import` or `plan amend` imports a new item (no `<item>/P` yet), it looks for items that a merged intake added: an intake issue (`kind/plan`, task `intake`, touching this plan file) that is merged or closed as completed, and the merged PR into the default branch that links it (newest intakes first, until every new item has an owner). The plan file is parsed at the merge commit's first parent and at the merge commit (missing at the parent: no ids; present but unparsable at either, or a merge commit GitHub does not know, which it answers with 404 or 422: that intake is skipped with a note on stderr); the item ids only the later one has were added by that PR, and one counts only while the local item (id, title, area, depends, tasks with title, touch, depends, size, kind and risk, UCs) equals the item in the plan file on the default branch (that file missing or unparsable: nothing counts). Their plan task `<item>/P` is made already merged and closed ("Done by intake #N ... PR #M") and the epic and tasks are promoted on the same run, so no second plan PR is needed. Otherwise (intake open, or its PR did not add the item) the plan task is made `ready` as before.

`plan import` also treats the default branch itself as proof: when the plan file there is byte-identical to the local one, each plan task that is new or open and `ready` (made by bosun, not adopted; one in any other state is left to whoever works on it) has nothing left to commit and is closed as completed with state `merged` (a new one is made so, an existing one gets a comment saying why), so its epics and tasks promote on the same run; `data.on_default` lists them. A file that differs in any byte (a trailing newline included) closes nothing. `--keep-plan-tasks-open` keeps them open and lists them in `data.on_default_open`. `plan amend` never does this: a new item of an amendment counts as merged only through its intake. A failed read of the file there closes nothing and adds a warning. A task's `allow:` enters its metadata (at import, and at `plan amend` for an existing task) only when the same task in the plan file on the default branch has that list with the same `touch`, `depends`, `kind` and `risk` (a local `touch: **` never borrows main's `allow`); otherwise the task gets none and a warning names it (docs/plan-format.md).

Handoff and relay: a root hands off with `bosun handoff` and the next root starts with
`bosun resume --handoff` (details in §5). A root relays after each merged milestone, or after
`waves.relay_waves` waves (default 6, in `.bosun/limits.toml`), whichever comes first.
The steps are `bosun handoff`, then `bosun spawn --root --handoff`, which returns
`create_session` for a fresh root (`environment_id` from `[cloud]` in `.bosun/bosun.toml`, set to the
shared `keelstack` environment; else the caller's), then `bosun spawn --root --record --from -`, which returns
`archive_session` for the old root. bosun never calls these tools itself (D29).

Commit trailers (traceability): every agent commit carries `Bosun-Session: <session>`, `Bosun-Task: <issue>` and, when known, `Bosun-Model: <model>`. One helper is the source of truth: `bosun trailers stamp <msgfile>`, offline, appends the ones the message lacks (session from `BOSUN_SESSION` as D31; task from `BOSUN_TASK`, else the issue of this session's cached lease; model from `BOSUN_MODEL`, else `ANTHROPIC_MODEL`; an unknown value is left out). It never rewrites a trailer that is there and runs idempotently, above any editor comment lines. `bosun trailers install` writes `.git/hooks/commit-msg` (marker `# bosun:trailers`) that calls it and never blocks a commit; it refuses (exit 3) to replace a hook it did not write, and the SessionStart hook runs it. `bosun pr` lists the PR's commits (merge commits skipped) and reports in `data.trailers` `{checked, unread, required, missing: [{sha, missing: [key]}]}`; a commit lacks a trailer when `Bosun-Session` or `Bosun-Task` is not in its last paragraph. That is an exit-0 note by default; with `[trailers] require = true` in `.bosun/bosun.toml` (set it only once `.bosun/version` pins a release that reads it) it is an error (exit 1) whose `data.trailers` lists the commits and whose `fix` says how to redo them stamped without a force-push. Rollback without the agent: `bosun trailers list <session>` prints the session's commits (newest first, from origin/main; exact match on `Bosun-Session`, or `<session>/<task>` of its wave agents) and `data.revert`, a `git switch -c … && git revert --no-edit <shas>` recipe; plain git does the same: `git log --fixed-strings --grep='Bosun-Session: <session>'`. A squash merge keeps the trailers only if the squash message does.

Trailers give traceability, not identity: they are text any author can write, so nothing may trust them for who approved or who may merge (that stays with signed approvals, §8). `bosun pr` with `[trailers] require = true` also checks the local commits `origin/<base>..HEAD` before it creates a PR, so a refusal leaves no draft PR. Keys match without regard to case; a line like `#123` is body text, and only `# text` or a lone `#` is an editor comment. A squash merge carries every session of the PR in one commit message (GitHub joins the commit messages), so `bosun trailers list` finds the squash under each of them; switching the repo's squash message setting to the PR body (or title only) drops the trailers, and then the rollback recipe finds nothing.
