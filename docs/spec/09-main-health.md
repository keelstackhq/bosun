## 9. Main-health, cost and spend guard

Main-health:
- The main-health workflow runs on each push to main and weekly. It opens one main-red issue on
  failure and closes it on recovery.
- The required check main-open fails every non-mainfix PR while main is red.
- Both workflows run the bosun release pinned in `.bosun/version` of the base commit (main-open, `pull_request_target`) or the default branch head (main-health), never PR code; while the pin lacks the command they run a shell fallback that posts the same status or issue. The main-open fallback is stricter than `bosun gate main-open`: it reads only the PR's own labels from the event, not linked issues. The main-open job is named `judge`; `bosun gate main-open` posts the `main-open` status. main-health ignores `workflow_run` events that are not pushes of this repo.
- `bosun gate main-open --pr N` posts the `main-open` status on the PR head: success while main is open or for a mainfix PR; else failure and exit 4. main-open.yml skips a draft except when the mainfix label changes, which judges it at once; `ready_for_review` judges it again. Only the label `bosun:kind/mainfix` makes a mainfix: on the PR, or on a linked issue that is open and not a pull request. A task marker in a body is never trusted (labels need triage rights, bodies do not).
- `bosun main-triage` bisects the merged PRs in code and names the first bad one.
  `bosun main-triage --good REV [--bad REV] [--run CMD]` bisects the first-parent commits between
  good and bad (bad defaults to HEAD) in temporary worktrees. `--run` is a shell command, non-zero
  is bad; the default is `bosun gate test --all`. It prints the first bad sha, subject and PR.
- The default fix is `bosun revert <pr>` as a kind/mainfix PR. A forward fix is allowed only if it
  is smaller.
- `bosun revert <pr>` needs a merged PR (else exit 3). It reverts the merge commit (`-m 1` for a
  merge) on the new branch `bosun/revert-<pr>` from the default branch, pushes that branch (never
  the default branch, never with force), opens a PR "Revert #<pr>: <title>" with the body marker
  `<!-- bosun:revert <pr> -->` and the main-red issue, and labels it `bosun:kind/mainfix`. Main-red
  does not block it. It works in a temporary worktree, so the caller's checkout is never touched. A revert
  conflict is exit 1: revert by hand or make a forward fix. `data.warning` flags a PR with more than
  one commit whose merge commit has one parent (a possible rebase merge: only the last commit is reverted).
- Each main-red opens a lesson.
- Every escaped defect teaches a check: an incident (a new main-red, a reverted PR) opens one issue "Which gate missed this? <what>" with the label `bosun:process-fix` (not a task: no `bosun:task` marker, no process-red exemption). The body links the evidence (run or PR), names the commit range (or says to find it with `main-triage --good REV`) and lists three checkboxes: root cause; the tightest loop that could catch it (local, CI, nightly); the proposed gate or test. It is deduped per incident by the body marker `<!-- bosun:gate-missed KEY -->` over open and closed issues: KEY is `main-red:#N` (main-health, only when it opens the main-red issue), `pr:N` (`bosun revert N`, or by hand) or `run:URL`. `bosun gate-missed (--pr N | --run URL) [--range GOOD..BAD]` opens or reuses it by hand (`data.issue`, `data.created`; a kill switch stops it; neither or both of `--pr`/`--run` is exit 2). In main-health and revert the result is `data.gate_missed` (`{issue, created}`, or `{error}`), and a failure there never changes the exit code. A revert merged by hand is covered by `gate-missed --pr N`.
- `bosun main-health --result R [--run-url U]` does this: `failure` opens the main-red issue (if none is open) and captures a `main-red` lesson; `success` comments and closes it; `timed_out` and `startup_failure` count as `failure`; any other result changes nothing. `success` closes every open main-red issue; two parallel failures keep the oldest issue. On every success or failure it re-judges every open PR (`main-open` status; a failed re-judge makes the exit 1), so queued PRs cannot auto-merge into a red main. Repeated main-red episodes hit the same open lesson (same signature, §6 dedupe). On `success` it also checks the queued tasks (auto-merge on). Review tasks are out of scope: `bosun wait --pr` does not report conflicts (CI does not run on a conflicting PR, so the wait times out). For each open `bosun:state/queued` issue it takes the PR of the newest `task-pr` record (§4) from a writer (never a PR found through a body link) and reads that PR, which must be open and link the task. One whose `mergeable_state` is `dirty` gets one `{"bosun":"conflict","pr":N,"head_sha":..,"base_sha":..}` record (no session) on the task and one comment on the PR (head and base sha, "merge main into <branch>, resolve, push; auto-merge stays on"), which wakes the session subscribed to the PR. Both are posted once per PR and head sha (the base sha moves with every update of main, so it is only information in the record), judged by the record (any user's record counts: a forged one only suppresses the comments). The task state does not change: auto-merge lands the PR once the branch is fixed and `reap` syncs queued to merged. `data.conflicts` lists `{pr, issue, posted, fix}`. GitHub computes `mergeable_state` lazily: `null` and `unknown` are skipped, never retried, and listed in `data.skipped_unknown`, so a conflict can be seen one run late. A failure while checking a task goes to `data.conflict_errors` (`{issue, error}`; a failed issue listing has no `issue`); it does not stop the other tasks and never changes the exit code. A `failure` run makes none of these calls. It checks no kill switch: it starts no work.
- `bosun heal [--pr N]` (self-heal, `[mode] heal_pr`; spec §18) acts on open PRs of this repo whose body's first `Closes #N` is a task (an issue with a state label) whose newest writer `task-pr` record names that PR (a body can be edited: a decoy never takes another task's lease), and whose head fails `ci-ok` (check runs of the Actions app; a draft's lone red `ci-ok` is excused). While the local `heal_pr` is `off` (gatekeeper) it reads nothing and prints `{knob: "off", brake: null, prs: []}`. Otherwise it checks the kill switch and takes `[mode]` from `.bosun/bosun.toml` on the default branch (a local edit cannot lift the brake), then recomputes the brake (`cli::metrics::window`, `mode::brake`); with `brake = "on"` and the brake tripped, `spawn` is capped at `notify`. Per red PR, in order: a head already healed is skipped (one round per head sha, counted by the task comment marker `<!-- bosun:heal head=SHA round=N action=A -->`; markers count from writers only, so a writer can suppress or exhaust the rounds, or delete one, as with every record); a task stop rule (§4: same signature 3x, empty fix round) skips it; after 2 rounds the task moves to `needs-human` once with a comment, so the digest asks (a state that cannot move there is skipped); a live lease holder gets a `send_message` in `next` (failing job names cut to a safe alphabet, the log signature of the first, `bosun ci-log N`; at most 500 chars); a dead holder gets a `create_session` fixer in `next` only with `spawn` and only when spawn checks 1-6 pass (no mainfix exemption; the caller must be registered; fixers of this run count toward the limits; a held prereq or a `[1m]` build model refuses; `[cloud] environment_id` is passed), else it is skipped. The caller's own live lease (taken for an earlier fixer) is no holder: a new red head gets the next round. A notify or spawn posts the round marker first; for a fixer the caller then takes the task lease once with the newest lease's `touch` (as `bosun spawn` does, `settle_race`; a lost race is an error row and still uses up that round), and the fixer runs `bosun join --parent <caller> --depth <d+1> --area heal-<task>`, stays in that touch and works on the PR branch without claiming. A live registry member in area `heal-<task>` refuses a second fixer. A newest lease with an empty `touch` gets no fixer (it would be unrestricted). An error on one PR becomes its row (`action: "error"`) and never drops the calls of the others. `data.prs` lists `{pr, head_sha, task, action, why}` with action `notify`, `spawn`, `needs-human`, `skip` or `error`.

Cost:
- Usage providers (D20): `claude-sessions` takes the `get_session` result of a session (asked for
  in `next`, passed back on stdin) and reads `usage.cost_usd`; `generic` estimates from turns and
  model with the prices in `docs/defaults.md`.
- `bosun budget record` posts the spend on the task issue and on the registry issue (created if missing), reads the `get_session` result from `--from -` (or a file), accepts `usage.cost_usd` at the top level or under `session`, and sets the task to blocked when the sum of its spend records exceeds `per_task_usd`. The record that blocks the task also opens a lesson of kind `budget` through the lesson capture of §6 (one lesson for all tasks; each further task over its cap adds a hit). A failed capture does not fail the record: it exits 0 with `lesson: {error, fix}`, and the spend must not be recorded again. The record is a `{"bosun":"spend",..}`
  comment.
- `bosun budget record --pr <n> [--pr <m> ...] [--from -|FILE] [--usd N] [--model M]` records spend on PRs, for PRs without a task issue (the guard checks every issue the PR links: Closes refs, `owner/repo#N`, URLs and the `bosun:task-pr` marker; a `get_issue` error fails the command before anything is written; a PR that links a task issue is refused with exit 3 and the fix `bosun budget record <issue>`; a task's spend goes to its issue: the per-task cap and the daily guard never see PR records). The cost is `--usd`, else `usage.cost_usd` of the `get_session` result (stdin with `--from -`); it is split evenly over the PRs (listed once each) and one `{"bosun":"spend","session","usd","at","model"}` comment is written on each PR (not on the registry issue: the daily guard counts what task records and review-ci write). `session` is `--session` (an orchestrator recording for a child it archives), else `session_id` (or `session.id`, `id`) of the result, else the caller; `model` is `--model`, else `session_context.model`, `external_metadata.last_served_model` or top-level `model` of the result, else absent, and is stored only (the report's `models` do not show it); `--provider` now defaults to `claude-sessions` (also for an issue). A PR that does not exist is an error (exit 1) and PRs are checked before anything is written; a PR that already has a record of that session is skipped and listed in `data.already_recorded` (a retry adds only what is missing), and when every PR has one it is a conflict (exit 3). The worker runs it at the end for each PR it made, or its orchestrator when archiving it (§5).
- The headline metric is cost per merged task.
- `bosun budget report [--month YYYY-MM] [--out DIR]` (default: the current UTC month; read-only on GitHub, no kill switch check) lists one row for every PR opened, merged or closed in the month (`created_at`, `merged_at` or `closed_at` of the pull), whether or not it has recorded spend. The PRs come from one list of all pull requests, newest update first, read until a page ends before the month (a PR with an event in the month was updated in or after it). A task names its PR in a writers' `task-pr` record; the lowest task number wins when several name one PR. Row fields, stable and sorted by `pr`: `pr`, `title`, `issue` (the task, else `null`), `sessions` (sorted ids of those spend records, else `null`), `models` (sorted: `model` of verdict records on the task and the PR, `to` of escalations, else `null`), `usd` (sum of the task's spend records and the spend records on the PR itself, `null` when none is recorded; the PR's records come from `spend_notes` too, and a session that has spend on the task is not counted again from the PR, nor twice on the PR), `tokens` (always `null`: no record carries tokens yet; unknown is never guessed), `outcome` and `merged_at` (`null` unless merged). `outcome` is `held` (merged, not undone by a merged `bosun/revert-<pr>` PR of this repo in the same list), `reverted`, `open` or `closed` (closed without a merge). Verdict, escalation and `task-pr` records count only from users with admin or write access; spend records count as everywhere else (§9 `spend_notes`: writers and the verdict bot). `usd` is the task's spend (plus the PR's own) over all time, not only in the month; a PR that bundles several tasks shows only the lowest task's spend for now. A task with spend and no `task-pr` record is listed in `data.skipped_no_pr`. `data` is `{month, rows, totals, written, skipped_no_pr}`; `totals` has `prs`, `prs_with_spend` (the page says "spend recorded for N of M PRs"), `usd` (the sum of the recorded spend, 0.00 when none, never a negative zero), `merged` (held + reverted), `held`, `reverted`, `merged_with_spend` and `held_with_spend` (merged or held PRs with recorded spend), `cost_per_merged_usd` and `cost_per_held_usd` (the recorded spend of those PRs over their count only, so an unrecorded PR never lowers the cost; `null` when that count is 0; the page labels them "with recorded spend, n=K") and `top_prs` (the 5 largest recorded `usd`, ties by lower `pr`: `pr`, `title`, `usd`). An unreadable `--month` is a usage error (exit 2). A revert merged in a later month turns an older month's `held` into `reverted` on the next run. With `--out` it creates DIR and writes `YYYY-MM.md` (totals, top PRs and a table; `-` for null) and `YYYY-MM.json` (`{month, rows, totals}`, pretty, final newline); `data.written` lists both paths. The files hold no clock reading, so the same records give the same bytes and a refresh changes them only when the data changed.
- `.github/workflows/budget-report.yml` keeps the reports: it runs weekly (Monday, 04:41 UTC; D-007) and by manual dispatch, never on a push (so the reports are as fresh as the last run; dispatch it after a merge to refresh), one run at a time per ref (concurrency group `budget-report-<ref>`; a newer run cancels the older one, and every step is repeatable). Every `uses:` is pinned by a 40-hex commit SHA with a version comment (the SHAs `release.yml` uses). A build job (read-only token: contents, issues, pull requests) builds bosun from source at main (the pinned release has no `budget report` yet), runs `bosun budget report` and uploads only the report files; the report job, the only one with `contents: write` and `pull-requests: write`, runs only git, gh and jq on those files (a file name other than `YYYY-MM.md` or `.json` fails the run) and never builds or runs repo code. The report is for the current UTC month, and the previous month too in the first 7 days of a month; the job copies the files into reports/budget/ and commits to the long-lived branch `bosun/budget-reports` (made from main when missing) only when a file changed. Its commits touch only reports/budget/** (the job refuses to commit any other path); it never force-pushes. It makes one draft PR "Budget reports" from the branch to main once (an existing PR, open or not, is never made again), never merges it, and keeps its body at a link to the current month's file and that month's totals. Setting: Actions must be allowed to create pull requests (a human step, Blocked in `docs/PROGRESS.md`).
- `bosun progress [--days N]` (default 7, read-only) reports it for the window of N days ending now: `merged` counts task issues closed with `closed_at` in the window (closed as `not_planned` or `duplicate` does not count), `spend_usd` sums the registry spend records with `at` in the window (unmerged work counts), and `cost_per_merged_task_usd` is `spend_usd / merged` (`null` when none merged); `reverted` counts those merged tasks whose recorded PR (the newest `task-pr` record by a writer) a merged PR from this repo's branch `bosun/revert-<n>` undid (one lookup by that head per task; no escape window, a revert made by hand is not seen), `held` is `merged - reverted` and `cost_per_held_task_usd` is `spend_usd / held` (`null` when none held); `task_cost_avg_usd` is the mean of the merged tasks' own spend (all time), and `tasks` lists `{issue, title, closed_at, usd}` by issue.

Spend guard:
- Below 80 % of the daily budget: normal.
- At 80 % or more: no new work; mainfix is exempt. `claim` checks it like spawn check 2 (exit 6).
- At 100 %: the janitor stops the sessions.
  The janitor runs `bosun budget check`, which returns one `interrupt_session` per live remote session in `next` (a wave agent `S/task` counts as `S`; never the caller's own session). It writes nothing, also works while halted, and a `daily_usd` of 0 turns it off. An interrupted session that resumes is still refused new work by spawn and claim.
- The day resets at 00:00 UTC.
- A task over `per_task_usd` goes to blocked and opens a lesson.
- Only the owner raises a budget (an R-gov change of limits.toml).
- Spend today is the sum of the `spend` records on the registry issue with `at` since 00:00 UTC, counting only records from commenters with admin or write access and from the workflow bot `github-actions[bot]`, which review-ci (mode b) posts as and whose permission lookup is not `write` (a forged record by anyone else is ignored here, in per-task sums and in `bosun progress`) (task issues hold the same records, so they are not summed again). `bosun status` reports it with `daily_usd` (from the default branch, as in §5) and its percent of it, and reports `integrity: reduced` when a stack uses a profile other than the built-in `rust`.
